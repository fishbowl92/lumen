# LUMEN

거울을 놓아 빛을 크리스털까지 보내는 3D 퍼즐 게임. 위에서 보면 막힌 길도, 빛을 위층으로 꺾으면 열린다.

- **플레이:** [ahskal.itch.io/lumen](https://ahskal.itch.io/lumen) (브라우저, PC 마우스·키보드)
- **엔진:** Unity 6.3 LTS (URP), WebGL
- **제작:** 2026-11-12 기획 → 11-16 동결, 1인 (AI와 협업, 아래 "만든 방식")

## 게임

| 모드 | 판 수 | 누구를 위한 것인가 |
|---|---|---|
| Fast Play | 11 | 새 요소마다 '아하' 하나씩 빠르게 훑는다. 마지막 판은 10×5×10 「빛의 정원 II」 |
| Normal Play | 21 | Fast 11판 사이사이에 직접 만든 연습 판 10개를 넣은 난이도 곡선 |

놓을 수 있는 것은 평면 거울, 승강 거울(빛을 위·아래 층으로), 분할기(빛을 둘로) 세 가지뿐이다. 광선은 항상 켜져 있어서 거울을 놓거나 돌리면 바로 다시 그려진다.

**별 점수.** 실패의 손실은 최소화하고 답의 질만 본다. 조작 수는 세지 않는다.

1. 빛을 꺾거나 나눈 거울 수가 최소보다 많으면 별 1개
2. 아니면 빛이 지나간 경로가 최단(Par) 이하면 별 3개
3. 그 밖(같은 거울 수로 더 돌아간 경로)은 별 2개

모든 판은 별 3개 해가 정확히 하나가 되도록 솔버로 검증했다.

| 입력 | 동작 |
|---|---|
| 좌클릭 | 받침대에 거울 놓기 / 놓인 거울 돌리기 |
| 우클릭 | 거울 회수 |
| 우클릭 드래그 · 휠 | 카메라 회전 · 줌 |
| WASD / 방향키 | 카메라 이동 |
| Tab | 층 보기 (전체 → 1층 → 2층 …) |
| Z · R · Home | 되돌리기 · 판과 카메라 리셋 · 카메라만 처음 위치로 |

## 만든 방식

무엇을 만들지, 어떤 규칙으로 할지, 어떤 판이 좋은 판인지는 사람(주민우)이 정하고, AI(Claude)에게는 그 결정을 실행할 코드·레벨 후보·검증 계산을 맡겼다. 모든 판단은 [결정 로그](docs/decision_log.md)에 "AI 제안 / 내 판단 / 근거"로 남겼다.

- **레벨:** 판마다 "처음 할 실수 → 깨닫는 순간"을 먼저 정했다([레벨 설계](docs/level_design_v2.md)). 소개 판은 직접 배치하고, 조합·연습 판은 의도를 조건으로 바꿔 생성기 후보를 만든 뒤 골라서 손질했다
- **검증:** 게임과 솔버가 같은 규칙 코드를 쓴다. EditMode 테스트 100개가 반사 규칙, 별 점수, 모든 판의 풀이를 매번 검사한다. 별도 파이썬 참조 구현과 무작위 격자 25,000개·무작위 레벨 19,945개를 대조해 결과가 모두 일치했다
- **기획서:** [기획서](docs/lumen_design_doc_v0.md) (규칙 명세, 엣지 케이스, 난이도 지표)

## 코드 구조

| 폴더 | 내용 |
|---|---|
| `Assets/Lumen/Core/` | 규칙 코어. 순수 C# (UnityEngine 참조 없음). 광선 계산 `BeamTracer`, 솔버 `Solver`, 판 상태와 별 점수 `LevelSession` |
| `Assets/Lumen/Core.Tests/` | EditMode 테스트 100개 |
| `Assets/Lumen/Game/` | 화면·입력·카메라. HUD는 런타임에 IMGUI로 그린다 |
| `Assets/Lumen/Resources/Levels/` | Fast Play 판 JSON (파일 이름 순서 = 판 순서) |
| `Assets/Lumen/Resources/LevelsNormal/` | Normal Play 판 JSON |

규칙을 Unity와 분리한 이유: 솔버와 테스트가 엔진 없이 같은 코드를 돌리게 해서, 화면에 보이는 결과와 솔버의 판정이 어긋날 수 없게 하려는 것이다.

**테스트 실행:** Unity에서 Window → General → Test Runner → EditMode → Run All.
